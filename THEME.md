# Zabi Components Theme Guide

How to load the Zabi Components theme in an app that uses Tailwind CSS v4, and
how to use its tokens in your own CSS.

To give the library your own brand, read [THEMING.md](./THEMING.md). It lists
the tokens an app may set and documents the `zabi-theme` generator. This file
does not repeat it.

## Quick Start

### With Tailwind in the app

```css
/* app.css */
@import "tailwindcss";
@import "zabi-components/theme-only";
@import "zabi-components/theme-dark-only";
```

That is everything. The theme file tells Tailwind to scan the package's
components, so the classes they use are generated by your build; there is no
second stylesheet to import.

### Without Tailwind in the app

```css
/* app.css */
@import "zabi-components/css";
```

The compiled stylesheet holds the utilities the components use, in light and
dark.

### Standalone theme files

`zabi-components/theme` and `zabi-components/theme-dark` are the same two theme
files with `@import "tailwindcss"` at the top, for a stylesheet that does not
import Tailwind itself. They still go through Tailwind's build.

```css
/* app.css */
@import "zabi-components/theme";
@import "zabi-components/theme-dark";
```

## Theme Files

| File | Description | Use Case |
|------|-------------|----------|
| `zabi-components/theme-only` | Every token, light values. No Tailwind import. | Apps that import Tailwind themselves |
| `zabi-components/theme-dark-only` | Dark role remaps. No Tailwind import. Needs the light theme. | The same apps, for dark mode |
| `zabi-components/theme` | `theme-only` with `@import "tailwindcss"` | A stylesheet without its own Tailwind import |
| `zabi-components/theme-dark` | `theme-dark-only` with `@import "tailwindcss"`. Needs the light theme. | The same, for dark mode |
| `zabi-components/css` | The compiled stylesheet | Apps without Tailwind |
| `zabi-components/colors` | The tokens as plain custom properties, light and dark | Apps that want only the variables |

The full matrix, the legacy `dist/` paths and what each file contains are in
[docs/theme-imports.md](./docs/theme-imports.md).

## Dark Mode

Import the dark theme file after the light one. It only remaps roles; the raw
palettes (`--zabi-brand-*`, `--zabi-accent-*`, `--zabi-base-*` and the other
ramps) are declared once, in the light theme, so the dark file does nothing on
its own.

Dark is switched on the `<html>` element, by an attribute or by a class:

| On `<html>` | Result |
|---|---|
| nothing | light, also on a dark system |
| `data-theme="light"` | light |
| `data-theme="dark"` | dark |
| `data-theme="auto"` | follows the system (`prefers-color-scheme`) |
| `class="dark"` | dark, the same as `data-theme="dark"` |

Following the system is opt-in:

```html
<!-- Follow the phone's setting, with no script -->
<html data-theme="auto">
```

To switch from a script:

```javascript
document.documentElement.dataset.theme = "dark"; // "light" | "auto"
// or
document.documentElement.classList.toggle("dark");
```

The details (`color-scheme`, why the attribute goes on `<html>` only, what
`ThemeToggle` reads) are in [THEMING.md](./THEMING.md#light-dark-and-auto).

## Using the Tokens

Components paint with **roles**: tokens that say what a colour is for and are
already the right value in each mode. Use the same roles in your own CSS.

- `--color-surface-base` / `-raised` / `-elevated` / `-overlay` - Surface levels: page, cards, nested cards, floating panels
- `--color-surface-inset` - A recessed area on a card (a well); see THEMING.md, Surface elevation levels
- `--color-headline`, `--color-body`, `--color-description`, `--color-caption` - Text
- `--color-border` - Borders and dividers
- `--color-action-primary`, `-hover`, `-active` - Primary actions
- `--color-on-brand` - Text on a primary fill (`--color-action-primary-text` follows it)
- `--color-accent`, `-hover`, `-active`, `-subtle`, `-border`, `-text` - The second brand colour
- `--color-on-accent` - Text on a solid accent fill
- `--color-link`, `--color-focus-ring` - Links and the focus ring
- `--color-focus-ring-muted` - The neutral ring of ghost and link controls (`.focus-ring--muted`)
- `--color-control-border` (`border-control-border`) - The edge of a control that has nothing else to be seen by, such as the outline of an empty Rating star. `--color-border-strong` is a decorative edge and is under 3:1 on the dark elevated and overlay surfaces
- `--color-success`, `--color-warning`, `--color-error`, `--color-info` - States, each with `-subtle`, `-border` and `-text`

The full list is in [THEMING.md](./THEMING.md#roles-read-them-do-not-set-them).

### In CSS

```css
.my-element {
  background-color: var(--color-action-primary);
  color: var(--color-on-brand);
}
```

### In Tailwind classes

```html
<div class="bg-card text-headline border border-border">
  A card surface with headline text
</div>
```

## Your Brand

Generate one file from your brand colour and import it after the theme. It
covers light and dark.

```bash
npx zabi-theme --brand "#C17B00" --neutral "#78716c" --out src/lib/brand.generated.css
```

```css
@import "tailwindcss";
@import "zabi-components/theme-only";
@import "zabi-components/theme-dark-only";
@import "./lib/brand.generated.css";

:root {
  --font-family-heading: "Your Display Font", var(--font-family-sans);
}
```

Which tokens an app may set, what the generator checks and what does not
follow an override: [THEMING.md](./THEMING.md).

## Adding Your Own Tokens

A token of your own goes in a `@theme` block after the theme import. Tailwind
then generates utilities for it (`bg-quiz-gold` here), next to the library's.

```css
@import "tailwindcss";
@import "zabi-components/theme-only";

@theme {
  --color-quiz-gold: #d4a017;
}
```

Use a name the library does not use. The library's own tokens are set on
`:root`, as THEMING.md describes, not redeclared in `@theme`.

## Common Pitfalls

### Pitfall 1: Importing the compiled stylesheet as well

**Wrong:**
```css
@import "tailwindcss";
@import "zabi-components/theme-only";
@import "zabi-components/css"; /* a second, finished Tailwind build */
```

**Correct:**
```css
@import "tailwindcss";
@import "zabi-components/theme-only";
```

Two Tailwind builds cannot be sorted into one order, so responsive variants
lose to plain utilities from the other build. See
[docs/theme-imports.md](./docs/theme-imports.md), "Tailwind together with the
compiled stylesheet".

### Pitfall 2: Double Tailwind Import

**Wrong:**
```css
@import "tailwindcss";
@import "zabi-components/theme"; /* This also imports Tailwind! */
```

**Correct:**
```css
@import "tailwindcss";
@import "zabi-components/theme-only"; /* Use theme-only */
```

### Pitfall 3: Overrides Before the Theme

**Wrong:**
```css
@import "./lib/brand.generated.css"; /* the dark theme below wins where both set a token */
@import "zabi-components/theme-only";
@import "zabi-components/theme-dark-only";
```

**Correct:**
```css
@import "zabi-components/theme-only";
@import "zabi-components/theme-dark-only";
@import "./lib/brand.generated.css";
```

### Pitfall 4: Missing Dark Mode Import

If you want dark mode support, you must import the dark theme file:

```css
@import "tailwindcss";
@import "zabi-components/theme-only";
@import "zabi-components/theme-dark-only"; /* Don't forget this! */
```

### Pitfall 5: `theme()` for a Colour

Tailwind's `theme()` function is replaced at build time with the token's light
definition, so `theme(colors.brand.600)` is the light step in dark mode too.
Use the variable, which is resolved in the browser:

```css
.custom-class {
  color: var(--color-brand-600);
  background: var(--color-surface-elevated);
}
```

## Troubleshooting

### Components Look Unstyled

1. Check that the theme is imported, after Tailwind
2. Check the package version: the theme files in 8.0.0 and earlier left components unstyled
3. Check the browser console for CSS errors

### Dark Mode Not Working

1. Ensure dark theme file is imported
2. Check that `class="dark"` or `data-theme="dark"` is on `<html>`, not on an element inside it
3. To follow the system, set `data-theme="auto"`; nothing follows it by default
4. Check that the light theme is imported too: the dark file only remaps its tokens

### Brand Colours Not Updating

1. Check that the brand file is imported after both theme files
2. Check that the overrides are on `:root`, not on an element inside the page
3. Check that it sets `--zabi-brand-*`, not `--color-brand-*`
4. Restart the dev server
