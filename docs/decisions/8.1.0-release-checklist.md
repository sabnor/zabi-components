# 8.1.0 release checklist

Written 2026-10-06 for the person who publishes 8.1.0. The branch is
`release/8.1.0`; the version commit `chore: prepare version 8.1.0` is the last
commit on it, so the tag lands on what was tested. npm `latest` is 8.0.0 today
(8.0.1 was never published; its fixes are in 8.1.0).

## Verified, and by which run

All of these were run on the version commit, once each, by the release
manager: `npm run check`, `npm test`, `npm run test:themes`,
`npm run test:e2e`, `npm run build:lib`, `npm pack`, and a scratch install
that resolves every `exports` target and runs `zabi-theme` from the installed
package. The counts are in the release report.

- Upgrade safety from 8.0.0, by comparing the published 8.0.0 package with
  this build: no file removed from `dist`, no `exports` path removed, no root
  or entry-point export removed, no component prop removed or made required,
  no custom property removed from the CSS files except Tailwind's own
  `--color-black` (generated from utility use, not a theme token). The one
  structural change is that the dark theme files no longer carry the
  `--zabi-*` ramps (decision D5): import the light theme first. Changed
  defaults and appearance are in the changelog's upgrade notes.
- Accessibility and behaviour review of everything added after beta.2, once,
  in Chromium: keyboard, focus, names and roles, 200% text, 375px, light and
  dark, reduced motion. Findings fixed: decisions D89 to D95.

## Only a person can check

In this order; each takes a few minutes.

1. **A real phone (iOS Safari), the docs site's `Select` page and any form of
   yours.** `Select` changed the most: the native control before hydration,
   the handover to the custom list, the `combobox` trigger, the sheet. Real
   keyboards and the on-screen keyboard behave differently from emulation.
2. **A screen reader (VoiceOver on iOS or macOS) on `Toaster`.** The toast
   group is named by its first line and contains it, so it may be read twice;
   naming it by type was parked until someone listens.
3. **A screen reader on the single `Toast`, on `ColorPicker`'s popover and on
   `BottomSheet` with snap points.** Focus after a dismissed toast, the
   Escape and focus path of the picker, and the grip button are the parts
   that were reasoned about but not heard.
4. **Safari (macOS) and Firefox, the `AppShell` page and the forms page.**
   Everything was run in Chromium. Safari draws native date and time inputs
   its own way (`DateField`, `TimeField`); Firefox differs on focus rings.
5. **`SwipeableListItem` and `PullToRefresh` on a touch screen.** Swipe,
   pull and release were emulated, not done with a finger.
6. **Windows High Contrast, `BottomTabBar` and the current-page marks.** The
   current tab shows in emulated forced colours; a badge is clipped.
7. **Your own theme (brand and accent), light and dark, `Progress` and a
   form.** The field edge got darker and `Progress` follows the primary
   action; both change an app without a code change.

## Recorded but not fixed

See "Release round: reviewed, and not fixed in 8.1.0" in
`8.1.0-qa-handover.md`: single `Toast` focus after dismissal, BottomSheet grip
overlapping the first title line, a few cosmetic findings in
SwipeableListItem, AvatarGroup and BottomTabBar, the dark field edge on
overlay surfaces (about 2:1, decision D86), and screen-reader questions.

## Rolling back a bad publish

A published version cannot be reused or replaced. If 8.1.0 turns out bad:

```sh
npm dist-tag add zabi-components@8.0.0 latest
```

so `npm install zabi-components` gives 8.0.0 again, then fix forward with a
patch release (8.1.1) and move `latest` to it with
`npm dist-tag add zabi-components@8.1.1 latest`. `npm deprecate
zabi-components@8.1.0 "reason"` warns people who already installed it.
Unpublishing is possible only within 72 hours and is a last resort.
