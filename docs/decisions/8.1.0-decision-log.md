# Decision log for 8.1.0 (2026-10-05 to 2026-10-06)

Design, API and behaviour decisions made while building 8.1.0 from the
Quizrundan app's component spec ("Zabi components to add"), its gaps file
(entries Z-001 onward) and the reviews that came with them. One entry per
decision: the options where there were any, what was chosen, why, and what
reversing it would take.

**Whose decisions.** Entries that quote Sabina or say "Sabina's ruling" are
the owner's. Every other entry was settled by the team manager, the agent
that planned and committed this work, to whom she delegated such questions.
She can overrule any of them. "Team lead" is the coordinating agent that
passed her instructions on.

**Reading notes.** Entries are in the order they were made; a later entry
can revise an earlier one and says so (D58 has a revised version further
down). Hashes are commits on `release/8.1.0`. Codes such as C3, M1c, RAD,
SEL, HYD and FORM name work packages, listed in `8.1.0-backlog.md`. "QA"
is a review pass by an accessibility and QA agent; A-H1 and the like are
its finding numbers. "Gates" are `npm run check`, `npm test`,
`npm run test:themes`, `npm run test:e2e` and `npm run build:lib`. Betas
were built locally as tarballs and never published. What is known wrong
and unreviewed is in `8.1.0-qa-handover.md`.

D0. Branch: stay on release/8.1.0. npm has 8.0.0, package.json 8.0.1 unreleased; the spec is additive features -> minor. No new branch.

D1. Rating `clearable`: spec says "tap the selected star again to clear". Standing rule (Sabina, 2026-09-30): single selection never clears on a repeat press. Chosen: keep the `clearable` prop, but it renders a separate clear control (and Delete/Backspace clears); a repeat press on the selected star is a no-op. Why: follows her explicit rule and still lets a rating be left empty. Reverse: make the star click handler set null when value === star and clearable.

D2. prefers-color-scheme: opt-in via `data-theme="auto"` on the root; `data-theme="dark"|"light"` and `.dark` force a mode. Not automatic. Why: following the OS by default would turn existing `.dark`-class consumers dark on OS-dark devices, a visible break. Reverse: move the auto rules to bare `:root` under the media query.

D3. Accent: `--zabi-accent-*` defaults to the citron ramp; `--color-accent*` roles added; `energetic` tokens stay as they are. Additive, nothing renamed.

D4. Parallel work: each engineer works in a git worktree of its own; the manager reviews, then commits onto release/8.1.0, resolving index/catalog/CHANGELOG overlaps.

Reverse: have build-css.js emit the ramps in a :where(:root) block in the dark files.

## D82 9.0 changes the default typeface to the platform UI face (2026-10-06)

## D85 Overrides can be set per mode with `{ light, dark, both }` (Z-037, 9d781ee)
Options: a themable `--zabi-surface-raised-light` token; separate options; a nested `overrides` shape.
